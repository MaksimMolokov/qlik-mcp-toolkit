# Источник MCP и версионные различия

Сервер: `qlik-sense-mcp-server` (сторонний пакет, PyPI), исходники
https://github.com/bintocher/qlik-sense-mcp. Подключён через `uvx ... --stdio`
(регистрация — скилл `mcp-qlik`, `Work\.claude\skills\mcp-qlik\`).

⚠️ **Исправлено 07.08.2026 — предыдущая версия этого файла ошибалась.**
Раньше здесь утверждалось «`uvx` резолвит пакет заново на каждой машине/
запуске без пина» — это НЕ так на практике: `uvx <пакет>` без явной версии
кэширует резолвинг по точной сигнатуре команды и переиспользует его на
последующих запусках, не проверяя PyPI на новый релиз (нужен `--refresh`
или очистка кэша `uv`). Живая проверка 07.08.2026 (файловая система,
`%APPDATA%\uv\tools\qlik-sense-mcp-server\Lib\site-packages\`) подтвердила
установленную версию **`qlik_sense_mcp_server-1.5.1`** (релиз от 1 июня
2026), тогда как на GitHub уже **v1.7.2** (31 июля 2026, +5 релизов). Пакет
не обновлялся с момента первого резолва.

✅ **Апгрейд до 1.7.2 подтверждён живьём 07.08.2026** — установлен
`qlik_sense_mcp_server-1.7.2` (`uv tool upgrade`), Claude Code перезапущен
для переустановки stdio-соединения. Modern-схема `engine_create_hypercube`
и `comment`-поля подтверждены реальными вызовами (`live-test-results.json`
-> `post_upgrade_verification_2026-08-07`). Баг реконнекта
(`CreateSessionObject` WS-таймаут ~180с) апгрейдом до 1.7.2 НЕ устранён.

⚠️ **11.08.2026 — найдена и исправлена вторая проблема с версией**: прод-
инструмент `uv tool install`'ился из git нашего собственного форка
(`github.com/MaksimMolokov/qlik-sense-mcp`), а не из PyPI — версия "1.7.2"
в `uv tool list` была версией, зашитой в форк на момент его создания
07-10.08, апстрим на ней и застрял. Переустановлен `uv tool uninstall` +
`uv tool install qlik-sense-mcp-server` из PyPI → официальный **v1.9.0**
(апстрим выпустил 1.8.0/1.8.1/1.9.0 подряд 11.08.2026, включая заявленный
фикс реконнект-бага новым health-check механизмом).

✅ **Схема-уровень подтверждён live 12.08.2026** (новая сессия Claude Code,
`get_about` прошёл 3.085с, `uv tool list` подтвердил `qlik-sense-mcp-server
v1.9.0` на диске, все 12 JSON-схем инструментов прочитаны напрямую у
работающего MCP-клиента): `get_app_variables` теперь всегда отдаёт объекты
(не строки), `get_app_object`/`get_app_sheet_objects` в описании инструмента
несут `fields_used`/`measures`/`dimensions`, `engine_create_hypercube`
описывает `field_not_found`/`did_you_mean` — всё совпадает с CHANGELOG
1.8.0-1.9.0. **Новых инструментов в JWT-режиме апстрим НЕ добавил** —
список из 12 tool-имён не изменился ни разу за 1.7.2→1.9.0 (в cert-режиме
добавились `update_task_schedule`/`delete_task_schedule`, недоступны нам).
**Баг реконнекта (`CreateSessionObject` ~180с) СХЕМОЙ не проверяется** —
`get_about` лёгкий QRS-вызов, не холодный Engine-коннект; правило "до двух
ретраев" остаётся обязательным до отдельного стресс-теста с реальным
`engine_create_hypercube` после паузы. Подробности —
`qlik-mcp-data-access/references/tool-catalog.md`, раздел «Апгрейд до
1.9.0», и память `project_qlik_sense_mcp_reconnect_fix_pending_test`.

**Всё равно не полагайся на номер версии как единственный источник правды**
— он может смениться при переустановке/апгрейде вне контроля этого скилла.
Единственный надёжный источник правды о параметрах КОНКРЕТНОГО вызова —
живая схема, которую тебе показал MCP-клиент СЕЙЧАС (см. раздел «Как
определить, какая схема реально активна» в `tool-catalog.md`).

Живой снимок на 2026-08-04/05/07 зафиксирован в
`qlik-mcp-data-access/references/tool-catalog.md` и
`.../live-test-results.json` — используй как ориентир, но при расхождении с
реальностью доверяй реальности. Полный разбор версионного разрыва и
