# qlik-mcp-data-access

Библиотека ПОДГОТОВКИ и ВАЛИДАЦИИ аргументов для инструментов `mcp__qlik__*` —
сами инструменты вызывает только агент (нативный tool call), скрипты этого
скилла к MCP-транспорту доступа не имеют. Используй функции ниже вместо
разовых самодельных JSON-объектов.

## Живая схема — не версия из документации

Единственный источник правды о параметрах — то, что тебе показал MCP-клиент
в ТЕКУЩЕЙ сессии для конкретного инструмента. `references/tool-catalog.md`
фиксирует снимки на 2026-08-04/05/07 — используй его как подтверждённый
ориентир, но при любом расхождении с реальной схемой вызова доверяй
реальности, не файлу.

✅ **`qlik-sense-mcp-server 2.0.2` — схема и поведение подтверждены живьём
16.08.2026** (2.0.0 13.08 → 2.0.1/2.0.2 апстрим 13-14.08, у нас обновлено и
перепроверено 16.08.2026). Modern-схема `engine_create_hypercube`
(`sort_by`/`sort_order`/`limit` на верхнем уровне) и `comment` в
`get_app_details` подтверждены живьём ещё на 1.7.2, актуальны и на 2.0.2.
**Новое в 2.0.0**: инструмент `engine_query` и `{filter}`-маркер в
`engine_create_hypercube` — проверены реальными вызовами. **Важное
изменение поведения на 2.0.2, найденное живым тестом, а НЕ в CHANGELOG
апстрима**: `engine_create_hypercube.dimensions[].field` теперь тоже
требует `[скобок]` для многословных имён (раньше — не требовал), падает
явной `invalid_expression`, а не тихо схлопывается — `hypercube_builder.
build_dimension()` уже оборачивает автоматически, руками не нужно. Гипотезы
из upstream CHANGELOG про explicit-error на out-of-range `offset` и на
перевёрнутые границы периода — живым тестом ОПРОВЕРГНУТЫ (сервер по-прежнему
тихо отдаёт пустой результат/сам переставляет границы, не ошибку). Детали —
`references/tool-catalog.md`, раздел "2.0.0 → 2.0.2".

## Модули

- `scripts/hypercube_builder.py` — `build_dimension()`/`build_measure()`
  (запрещают вычисляемые измерения и `If()` внутри агрегата; `build_dimension()`
  с 2.0.2 сама оборачивает `field` через `quote_field()` — руками скобки
  можно не добавлять),
  `set_analysis_clause()` (верная расстановка кавычек: числа без кавычек,
  текст в одинарных, диапазон в двойных), `check_row_budget()` (лимиты 5000
  строк / 9900 ячеек), `is_transient_connection_error()`,
  `is_jwt_bootstrap_error()` (второй, отдельный класс сбоя — таймаут JWT-
  бутстрапа, не Engine WS; найден 07.08.2026), `build_hypercube_request_modern()`
  (modern-схема v1.6.0+, подтверждена живьём, основной путь для
  `engine_create_hypercube`), `build_engine_query()`/`quote_field()` (v2.0.0+,
  подтверждены живьём 13.08.2026 — предпочтительнее для простого «сколько по
  чему»; `quote_field()` оборачивает многословные имена в `[скобки]`,
  обязательно для `group_by`/`metrics[].field`/`filters[].field` в
  `engine_query`, чего `engine_create_hypercube.dimensions[].field` не
  требует).
- `scripts/app_cache.py` — постоянный (не per-беседа) кэш семантики
  приложения по `app_id`+`reload_fingerprint` в
  `$QLIK_MCP_TOOLKIT_HOME/app-cache.json` (по умолчанию `~/.qlik-mcp-toolkit/`). Проверяй его ПЕРЕД
  `get_app_script`/`get_app_sheets`/`get_app_object` — это десятки тысяч
  символов контекста за раз, не читай их заново, если кэш свежий.

## Обязательное правило про таймауты (live-подтверждено 2026-08-04, расширено 2026-08-07)

`engine_create_hypercube` (и другие вызовы к Engine) может упасть с
`error_category: connection_error`, `failed_step: CreateSessionObject` (или
`GetTablesAndKeys` в `get_app_details`) и WebSocket-таймаутом ~180с —
известный баг сервера, не был исправлен вплоть до 1.7.2 (проверено живьём
07.08.2026). В 1.8.0 (11.08.2026) автор заменил механизм health-check
целиком — заявлено как исправление, но ЕЩЁ НЕ ПРОВЕРЕНО ЖИВЬЁМ на нашей
стороне (см. `tool-catalog.md`, раздел "Апгрейд до 1.9.0") — прошлые
похожие заявления (1.6.0+) на практике не подтверждались, так что **пока
не убирай правило ниже**. **Повтори тот же вызов до ДВУХ раз с теми же
аргументами, прежде чем сообщать об ошибке** —
после апгрейда зафиксирован случай, где потребовались ОБА ретрая подряд
(первая попытка и первый ретрай оба упали на ~180-230с, только второй ретрай
прошёл). Один повтор часто (но не всегда) достаточен — стейдж-2 регрессия
(07.08.2026, ~22 живых вызова, ещё на 1.5.1) зафиксировала минимум два случая,
где сбой повторился СРАЗУ ПОСЛЕ успешного тёплого вызова к тому же приложению,
то есть это не строго «первый вызов после долгой паузы». Не пропускай повтор
только потому, что предыдущий вызов только что прошёл успешно.

Отдельно — **второй, отличный класс сбоя** (впервые пойман 07.08.2026,
цикл 006 стейдж 2): таймаут не на `CreateSessionObject`, а на самом
JWT-бутстрапе (`error_type: QlikConnectionError`, текст ошибки содержит
`JwtBootstrapError`/`csrftoken request failed`, ~47-60с). Диагностируется
через `hypercube_builder.is_jwt_bootstrap_error()`. Та же тактика (повтор
того же вызова) сработала, но стоит явно упомянуть в отчёте, если
встретится — это может указывать на проблему уровня сети/прокси, а не на
уже задокументированный баг реконнекта Engine.

## Правила hypercube

- Оцени `check_row_budget()` до отправки — произведение cardinality измерений
  не должно превышать 5000 без сужения через Set Analysis в measure.
- Ranking/top-N по значению самой меры/измерения — top-level `sort_by`/
  `sort_order`/`limit` (`build_hypercube_request_modern()`, подтверждено
  живьём с 07.08.2026, ОСНОВНОЙ путь). `max_rows` + `qSortByExpression`
  внутри dimension (`build_dimension(field, sort_by_expression=...)`) —
  fallback для отката/переустановки сервера без пина версии и для
  адресной выборки по списку известных ID
  (`build_id_list_sort_expression()`), где `sort_by` не подходит.
- Никаких вычисляемых измерений (`=Year(...)`, `=If(...)`) и `If()` внутри
  агрегата — используй готовые календарные поля и Set Analysis.
- Ответ сервера сам содержит `truncation_warning` с готовой подсказкой при
  усечении — используй её текст, не изобретай собственный.
- Подробный синтаксис Set Analysis, двухфазный паттерн для больших ключей,
  диагностика ошибок — `Work\MCP qlik\Инструкции\Быстрый старт\qlik-mcp-faq-for-cursor.md`
  (верифицирован против исходного кода сервера, совпадает с живой схемой).

## Что скилл НЕ делает

- Не вызывает `mcp__qlik__*` из Python — только агент, нативным tool call.
- Не хранит/не печатает JWT — токен вне зоны этого скилла (`mcp-qlik`,
  `Work\.claude\skills\mcp-qlik\`).
- Не вызывает изменяющие инструменты (`create_task`/`start_task`/...) — в
  JWT-режиме их и нет в схеме.
- Не заменяет `qlik-engine`/`qlik-qrs` (cert-based, независимый инструмент).
